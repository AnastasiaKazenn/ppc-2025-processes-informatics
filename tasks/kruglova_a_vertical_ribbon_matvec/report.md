## 1. Введение
Задача умножения матрицы на вектор является одной из базовых операций линейной алгебры и широко применяется в научных вычислениях, машинном обучении, численных методах и обработке изображений. Для матриц большой размерности вычислительная сложность данной операции становится существенной, что делает актуальным использование параллельных алгоритмов.

Ленточная вертикальная схема распараллеливания предполагает разбиение исходной матрицы по столбцам между процессами. Каждый процесс выполняет умножение своего блока столбцов на соответствующую часть вектора, формируя частичный результат, после чего глобальный результат получается с помощью коллективных операций. Данный подход позволяет эффективно распределить вычислительную нагрузку и продемонстрировать применение механизмов обмена данными и редукции в параллельных системах.

В рамках лабораторной работы реализованы последовательная и параллельная версии умножения матрицы на вектор с использованием ленточной вертикальной схемы, а также проведено их сравнительное исследование с точки зрения корректности и производительности.

## 2. Постановка задачи
**Формальная постановка:**  Для заданной матрицы `𝐴` размерности `𝑀×𝑁`, состоящей из вещественных чисел (std::vector<double>), и вектора `𝑏` длины `𝑁` (std::vector<double>),требуется вычислить результирующий вектор: `y = A ⋅ b`.

**Входные данные:** Вектор `V` (std::vector<float>) произвольной длины.
- `M` — целое число, количество строк матрицы
- `N` — целое число, количество столбцов матрицы
- `A` — матрица (std::vector<double>) размерности `M × N`, хранящаяся в построчном виде
- `b` — вектор (std::vector<double>) длины `N`

**Выходные данные:** `y` — вектор (std::vector<double>) длины `M`, являющийся результатом умножения матрицы на вектор `b`

**Ограничения:**
- `M ≥ 0`, `N ≥ 0`, алгоритм должен корректно работать при нулевых размерах
- Размерность матрицы должна быть согласована с длиной вектора (N)
- Параллельная MPI-версия должна поддерживать произвольное количество процессов и реализовывать ленточную вертикальную схему распределения столбцов матрицы и соответствующих элементов вектора `b`

## 3. Последовательная версия(Baseline)
Последовательная версия алгоритма реализует классическое умножение матрицы на вектор без использования параллелизма. Матрица `𝐴` хранится в построчном виде, и для каждой строки последовательно вычисляется скалярное произведение с вектором 
`𝑏`.
```cpp
for (int i = 0; i < rows; ++i) {
  double sum = 0.0;
  for (int j = 0; j < cols; ++j) {
    sum += matrix[(i * cols) + j] * vec_b[j];
  }
  res_y[i] = sum;
}
```
- Временная сложность: `O(M⋅N)`, где `𝑀` — количество строк матрицы, `𝑁` — количество столбцов.
- Потребление памяти: `𝑂(1)` дополнительной памяти (не считая входных и выходных данных).

## 4. Параллельная версия
### 4.1. Разделение данных
В параллельной версии используется вертикальная ленточная схема распределения данных. Матрица 

$A \in \mathbb{R}^{rows \times cols}$

разбивается по столбцам на size вертикальных лент:
- `base = cols / size`
- `rem = cols % size`
- процесс i получает `local_cols = base + (i < rem ? 1 : 0)` столбцов матрицы
- каждому процессу передаётся соответствующий фрагмент вектора `𝑏` длины `local_cols`
- каждая вертикальная лента содержит все `rows` строк, что позволяет вычислять частичный вклад в результирующий вектор
Для повышения эффективности передачи данных матрица предварительно транспонируется на корневом процессе, после чего распределяется по процессам как непрерывные блоки памяти.
 
### 4.2. Взаимодействие процессов
1. **Синхронизация параметров задачи**  
   Процесс 0 определяет размеры матрицы rows и cols и рассылает их всем процессам с помощью `MPI_Bcast`
2. **Распределение вектора `𝑏`**  
   Формируются массивы sendcounts и displs, определяющие количество элементов вектора 𝑏, передаваемых каждому процессу. Распределение выполняется с использованием `MPI_Scatterv`.
3. **Распределение матрицы**  
   На корневом процессе матрица предварительно транспонируется. Затем каждая вертикальная лента (набор столбцов) передаётся соответствующему процессу посредством `MPI_Scatterv`.
4. **Редукция результатов**  
   Каждый процесс вычисляет локальный вклад в результирующий вектор:
  
   $y_i^{(local)} = \sum_{j \in local_cols} A_{ij} \cdot b_j$

   Результатом является частичный вектор длины rows.
5. **Распространение результата**  
   Частичные векторы суммируются на корневом процессе с использованием `MPI_Reduce` и операции `MPI_SUM`, формируя итоговый результат `𝑦=𝐴⋅𝑏`.

### 4.3. Псевдокод алгоритма
```pseudocode
MPI_Init()
Получить rank и size

Если rank == 0:
    rows, cols ← размеры матрицы
MPI_Bcast(rows)
MPI_Bcast(cols)

Вычислить sendcounts и displs для столбцов

MPI_Scatterv(b → local_b)

Если rank == 0:
    транспонировать матрицу A → A_T

MPI_Scatterv(A_T → local_matrix)

local_res[0..rows-1] = 0
Для каждого локального столбца j:
    Для каждой строки i:
        local_res[i] += local_matrix[j][i] * local_b[j]

MPI_Reduce(local_res → global_res, SUM)

Если rank == 0:
    результат = global_res

MPI_Finalize()
```

### 5.3. Использование памяти

**В последовательной версии (SEQ):** в памяти хранится вся матрица `𝐴`, входной вектор `𝑏` и результирующий вектор `𝑦`.
**В параллельной версии (MPI):**
- процесс 0 хранит: полную матрицу `𝐴`, входной вектор `𝑏`, транспонированную матрицу, служебные массивы `sendcounts` и `displs`
- остальные процессы хранят: только свою вертикальную ленту матрицы, соответствующий фрагмент вектора `𝑏`, локальный частичный результирующий вектор длины `rows`.
Такая организация памяти снижает объём хранимых данных на каждом процессе и обеспечивает масштабируемость алгоритма при увеличении числа MPI-процессов.

В MPI-версии реализована стратегия разделения столбцов матрицы между процессами, что позволяет каждому процессу вычислять локальный вклад в результирующий вектор. Для сбора итогового результата использована коллективная операция `MPI_Reduce` с суммированием (MPI_SUM).

Несмотря на это, при увеличении размера задачи или числа процессов чистое вычислительное время локальных умножений масштабируется почти линейно.

Вывод: для подобных задач с высокой долей операций с памятью ключевым фактором ускорения является оптимизация распределения данных и уменьшение коммуникационных накладных расходов.

## 9. Приложение

```cpp
namespace {

std::vector<int> ComputeSendCountsAndDispls(int cols, int size, std::vector<int> &displs) {
  std::vector<int> sendcounts(size);
  const int base_cols = cols / size;
  const int rem_cols = cols % size;
  int offset = 0;
  for (int i = 0; i < size; ++i) {
    sendcounts[i] = base_cols + (i < rem_cols ? 1 : 0);
    displs[i] = offset;
    offset += sendcounts[i];
  }
  return sendcounts;
}

void TransposeMatrix(const std::vector<double> &matrix, std::vector<double> &transposed, int rows, int cols) {
  for (int i = 0; i < rows; ++i) {
    for (int j = 0; j < cols; ++j) {
      transposed[(static_cast<size_t>(j) * rows) + i] = matrix[(static_cast<size_t>(i) * cols) + j];
    }
  }
}

void LocalMatVecMul(const std::vector<double> &local_matrix, const std::vector<double> &local_b,
                    std::vector<double> &local_res, int rows, int local_cols) {
  for (int j = 0; j < local_cols; ++j) {
    const double b_val = local_b[j];
    for (int i = 0; i < rows; ++i) {
      local_res[i] += local_matrix[(static_cast<size_t>(j) * rows) + i] * b_val;
    }
  }
}

}  // namespace

bool KruglovaAVerticalRibbMatMPI::RunImpl() {
  int rank = 0;
  int size = 0;
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  MPI_Comm_size(MPI_COMM_WORLD, &size);

  int rows = 0;
  int cols = 0;
  if (rank == 0) {
    rows = std::get<0>(GetInput());
    cols = std::get<1>(GetInput());
  }

  MPI_Bcast(&rows, 1, MPI_INT, 0, MPI_COMM_WORLD);
  MPI_Bcast(&cols, 1, MPI_INT, 0, MPI_COMM_WORLD);

  std::vector<int> displs(size);
  std::vector<int> sendcounts = ComputeSendCountsAndDispls(cols, size, displs);

  int local_cols = sendcounts[rank];
  std::vector<double> local_b(local_cols);

  const double *global_b_ptr = (rank == 0) ? std::get<3>(GetInput()).data() : nullptr;
  MPI_Scatterv(global_b_ptr, sendcounts.data(), displs.data(), MPI_DOUBLE, local_b.data(), local_cols, MPI_DOUBLE, 0,
               MPI_COMM_WORLD);

  std::vector<double> transposed_matrix;
  if (rank == 0) {
    const auto &matrix = std::get<2>(GetInput());
    transposed_matrix.resize(static_cast<size_t>(rows) * cols);
    TransposeMatrix(matrix, transposed_matrix, rows, cols);
  }

  std::vector<int> mat_sendcounts(size);
  std::vector<int> mat_displs(size);
  for (int i = 0; i < size; ++i) {
    mat_sendcounts[i] = sendcounts[i] * rows;
    mat_displs[i] = displs[i] * rows;
  }

  std::vector<double> local_matrix(static_cast<size_t>(local_cols) * rows);
  MPI_Scatterv(rank == 0 ? transposed_matrix.data() : nullptr, mat_sendcounts.data(), mat_displs.data(), MPI_DOUBLE,
               local_matrix.data(), local_cols * rows, MPI_DOUBLE, 0, MPI_COMM_WORLD);

  std::vector<double> local_res(rows, 0.0);
  LocalMatVecMul(local_matrix, local_b, local_res, rows, local_cols);

  double *global_res_ptr = (rank == 0) ? GetOutput().data() : nullptr;
  MPI_Reduce(local_res.data(), global_res_ptr, rows, MPI_DOUBLE, MPI_SUM, 0, MPI_COMM_WORLD);

  return true;
}
```
